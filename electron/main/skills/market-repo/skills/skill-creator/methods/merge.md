# 技能融合与淘汰的方法（Merge & Retire）

本文件是 skill-creator 的「技能太多怎么办」子文档：数量膨胀或职能重叠时，先查重、后融合、再淘汰，不重复造轮子。

## 什么时候进入本节

- 技能数量明显膨胀，`use_skill` 盘点结果职能重叠、边界相邻
- 新需求出现，但不确定现有技能是否已覆盖（创建前查重）
- 用户抱怨"技能太多、找不到该用哪个"

## 处理步骤（按顺序执行）

### 1. 先查重

盘点全部技能（`use_skill` 不传参数，必要时按 domain 分域盘点），找出职能重叠者。查重对象包括：

- description 触发词高度雷同的两个技能
- 步骤流程覆盖同一能力面的技能
- 名称不同但产出物相同的技能

### 2. 融合优先

两个技能覆盖同一能力面、边界相邻时，合并为一个技能并删除被并入者。融合规则：

- 合并后重写 description，触发词收敛为统一集合，不保留"两个入口"
- 步骤保留各自独有的决策点，重复步骤只写一遍
- 输出模板取更能覆盖双方交付物的那个，另一份删除
- 不留"另一处也讲"的交叉引用——融合后的技能必须自洽
- 若融合产物体积过大（>500 行），按 `split.md` 拆成主体 + 子文档，不改变融合结论

### 3. 丢弃其次

长期未使用、已被替代、或边界模糊到无法维护的技能直接删除。判断标准：

- 最近使用记录（`.skills-usage.json` 的 lastUsedAt/useCount）长期为零
- 功能已被其他技能完全覆盖
- 边界模糊、无法写清"做什么/不做什么"，维护成本大于收益

保留"可能哪天有用"的技能是负债不是资产。

### 4. 不重复造轮子

新需求先查现有技能能否覆盖，能就不新建。每次创建前都做一次查重（用 `use_skill` 盘点 + description 关键词比对）。

## 执行说明

- 融合或丢弃前向用户说明判断与影响，获取确认
- 删除动作按 `generate.md` 第四步的 `delete` 流程执行（先确认，再删技能目录与 SKILL.md 文件）
- 融合/淘汰完成后重新盘点一次，确认技能池无残留重叠

## 融合完成标准

- [ ] 盘点完成，重叠项已列出并与用户确认
- [ ] 融合或淘汰动作已执行，被并/被删技能已移除
- [ ] 保留技能 description 自洽、体积合规（必要时已按 split.md 拆层）
- [ ] 向用户交付结论：保留哪些、融合哪些、删除哪些及原因
