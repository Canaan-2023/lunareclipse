# 技能创建与治理（Skill Creator）

## 为什么存在

每一个技能都是一份 SKILL.md：frontmatter 决定它何时被检索到、何时被触发，正文决定加载后怎么执行。本技能把"从想法到可用技能、再到长期治理"的完整决策固定下来。本技能自身就是"主体 + 子方法"结构的示范：主体只放入口判断与能力总览，详细方法拆到同目录 `methods/` 子文档，AI 用 `Glob`/`Read` 按需读取，不把全部内容塞进注入上下文。

## 能力总览（本技能所有能做的事）

| 你能提的需求 | 交给本技能的环节 | 详细方法在 |
|---|---|---|
| 从零创建技能 / 把工作流固化 | 捕获意图 → 设计 → 撰写正文 → 保存 → 自检 → 测试 | `methods/generate.md` |
| 修订、优化、升级现有技能 | 改 description、正文、字段、存放位置后重走自检 | `methods/generate.md` |
| 评估技能质量 / 规范体检 | frontmatter 校验 + lint + 威胁扫描 + 触发回读 | `methods/generate.md` |
| 技能数量膨胀 / 职能重叠 | 查重 → 融合优先 → 丢弃其次 → 不重复造轮子 | `methods/merge.md` |
| 单个技能体积过大 | 解剖主体与子方法，子文档按需读取 | `methods/split.md` |
| 技能盘点（查技能池有什么） | `use_skill` 不传参数或传 `domain` 盘点 | 主体（见下） |

## 什么时候用

- 用户从零创建技能、把当前工作流固化成技能
- 修订、优化、升级现有技能（改 description、正文、字段、存放位置）
- 评估技能质量、检查技能是否符合规范（当作一次"技能体检"）
- 为技能补测试提示词、验证触发与误触发
- 用户要求删除技能
- 技能数量膨胀，需要盘点、融合或淘汰时
- 技能体积过大，需要拆分治理时

## 主体入口判断（本文件内完成，不需要读子文档）

### 何时生成技能

满足全部条件才创建：

- **工作流可复用**——同一套步骤会跨任务重复出现，不是一次性操作
- **边界清晰**——能一句话说清"做什么、不做什么"
- **输出可预期**——交付物形态稳定，可给出模板
- **触发可识别**——用户会说出可匹配的请求原话

四问答不上来的工作流不值得固化成技能：要么太模糊，要么是一次性任务。此时向用户说明并建议调整范围。

### 何时沉淀技能

把散落在会话里的有效工作流固化为正式技能，满足：

- 同一步骤已成功执行过一次以上，流程验证有效
- 步骤含判断点——不只是"跑一条命令"，而是"按什么判断→做什么→输出什么"的决策链
- 复用价值明确——同类问题再次出现的可能性高

没有判断点的纯步骤清单更适合写成脚本或文档，不必固化为技能。

### 技能如何摆放

技能的真实存放地只有一处：**AI 自己的工作域**，分两个独立文件夹：

- **用户级**（`skills/`，扁平）：方法论、通用技能一个技能一个目录，如 `skills/{name}/`
- **领域级**（`skills_domains/{领域路径}/`）：按目录层级分类，领域 = 相对根的父路径，层级与数量不限

判定规则：有领域（目录层级）→ 领域级；平铺 → 用户级。领域由目录位置决定，frontmatter 的 `domain:` 字段仅为展示。命名 kebab-case、不含保留词。

**市场（商场）只做分发，不是技能的存放地**：市场条目是安装源，安装时复制进工作域后才被 AI 调用；AI 调用、生成、修改技能都发生在工作域，市场条目不做生成/编辑目标。需要分享时，才把工作域里已完成的技能经上传通道做成市场条目。

## 子文档路由（需要方法细节时按需读取）

本技能正文只承担入口与判断。进入实际执行后，用 `Read` 读取对应子文档获取完整步骤。子文档与本文件同目录，`use_skill` 加载本技能时返回体已带 `dir_path`（技能目录绝对路径），用绝对路径读取：

- **要动手创建/修改技能**（捕获意图、frontmatter 设计、正文结构、保存、自检、测试）→ `Read(file_path=<dir_path>/methods/generate.md)`
- **技能太多、职能重叠，要融合或淘汰** → `Read(file_path=<dir_path>/methods/merge.md)`
- **单个技能太长、要拆成主体 + 子方法** → `Read(file_path=<dir_path>/methods/split.md)`

若返回体中无 `dir_path`（旧版引擎），可先用 `Glob(path=<skills/skills_domains 数据目录>, pattern=<技能名>/methods/*.md)` 定位再读。子文档与 SKILL.md 同目录存放、随整目录分发，方法与"在技能里放脚本"同理：需要时定位、`Read` 读取，用完全部放在上下文之外。

## 完成标准

- [ ] 已按"何时生成/沉淀"判断该不该建技能，过了入口才继续
- [ ] 按需求路由到了对应子文档，没有跳过细节直接动手
- [ ] 产出物的 frontmatter、正文、摆放位置符合规范（对应子文档有逐条检查）
- [ ] 交付时向用户说明：技能路径 + 能力范围（或治理结论）
