# 以 AI 视角写提示词

## 读者是模型

提示词是模型照着执行的行为契约，唯一读者是模型。按写代码注释的心态落笔，会写出「出口」「落盘」「恒注入」「不构成违规」这类维护者才懂的话；模型读到的是噪音，还会开始揣测「什么算违规」。

每个 token 都计费，每句都要付阅读时间。仪式句成本加倍：先花 token 说「好的」，再花 token 说重点，模型还要花理解成本跳过前者。

## 什么时候用

- 写或改任何给模型看的文本：系统提示词、工具 description、技能、行为手册、持续指令
- 审查既有提示词的模型可读性，找措辞问题
- 把啰嗦指令压到只剩载荷，且不丢技术事实
- 落笔前需要先想清楚的重要判断

## 四步方法论

动笔或下判断前，四步走完再输出：

- **立根**：写下这次判断依赖的最底层事实。默认成立，允许后续推翻。
- **验底**：逐个过一遍依赖的前提。有直接证据的留下；拿不出证据的标为待验，不拿它推理。
- **顺推**：从根往上推，每步写明依据。直接得出的地方写出推导或标出假设；列出放弃的备选路径与放弃理由。
- **验证**：写三条可观测信号——结论为真会看到什么、为假会看到什么、出现什么就推翻它；再写结论落地谁受益、谁受损。写不出信号说明没想透，回顺推。

完成后自述一遍：结论为什么成立、推理分几步。能用最朴素的话讲清才算通过。

## 落笔八条

写或改完逐条过，任何一条不过都改到过为止。

1. **读者是模型**：把自己放在第一次读到这段文本的模型位置，问「这句让我知道该做什么吗」。只让维护者明白了什么的句子删掉。
2. **只留行为边界**：模型需要知道的只有做什么、何时用、不做的后果。常量名、函数名、内部组件名、注入机制、存储路径这些实现细节不进提示词。
3. **正面声明三要素**：做什么、何时用、不用的影响。例：「把一次完整思考流写入 thinking-log，供以后复盘回看。需要留痕时调用。不需要留痕就不调用，思考照常进行。」
4. **免责句式清零**：「不调用不构成违规」「不强制走它」「不调用也可以」凭空引入一个不存在的规则概念（违规），模型会开始揣测还有哪些没看到的规则。删掉，改写成可选动作的真实效果。
5. **每条指令回答四个问题**：这是什么、用它做什么、什么时候用、不用的后果。只写「它是什么」不写触发条件，工具与指令会被模型忽略。
6. **方法论与机制分层**：怎么思考放在独立小节；输出格式、上下文规则等机制约束单独列条。混排会让模型把方法论当可选项跳过去，把规则当建议。
7. **答为先，删仪式**：先写做什么，再写条件、理由、下一步。删掉开头的「好的/没问题/我来处理」与结尾的「以上是我的一些想法」。不写「我将」「我会」——读者要动作，不要执行者自述。
8. **短词，一句一个想法**：「修」不写「针对此问题实施解决方案」。DB/API/HTTP 这类标准缩写可用，cfg/impl/fn 这类自造缩写不用。每句不超过 20 词、主动语态、祈使句、代词只指明确对象。压缩与清晰冲突时清晰赢：为省 3 个字丢掉一个否定词，比多写 10 个字更贵。

载荷逐字：代码块、命令、路径、API 名、错误信息一个字符都不改。错误只取最短的决定性一行，不贴整段堆栈。文件名、端口、环境变量名不缩写、不改写。压缩永远不碰载荷。

## 用完整句子的场合

压缩是风格，清晰是底线。以下场景写完整句子：

- 安全警告与不可逆操作：先讲清后果，再给动作
- 步骤顺序不能被打乱的操作：一个动作一条完整指令
- 模型读不懂或重复问同一个问题：换成完整句解释
- 会持久化到外部的文本：写进代码、评论、提交、文档、issue、第三方消息，读者是另一个人
- 你向模型提问或给选项：完整句子，让回答一次到位

## 给既有提示词做体检

1. **通读全貌**：列出目标提示词涉及的全部文本，含引用它的其他文件，建立清单。
2. **确认模型真正读到的副本**：同一工具可能在实现内、注册表、手册里各有一份描述。以实际注入模型的那份为准，其余副本同步改。
3. **扫高危措辞**：搜开发者黑话（出口、落盘、恒注入、违规、强制、唯一、必须）与免责句式（不构成、不强制、不调用也可以）。
4. **按模型视角重读**：逐句问「这句让我知道该做什么了吗」，顺手删仪式句。
5. **核对载荷**：命令、路径、API 名、错误行逐字比对；否定词（不、别、只、除非、仅）一个都不丢。
6. **保守修订**：改措辞不改行为语义；用户定稿的方法论正文不动，只改周边引导与描述。
7. **复读收尾**：重读受影响段落，确认无残留黑话、无新增歧义。

## 发送前检查

1. 能向另一个模型复述这段提示词「让我什么时候做什么」，对方听完能正确执行
2. 文中没有开发者黑话、免责句式、只写是什么却不写何时用的指令
3. 方法论与机制分层清晰，读者不会把方法论当规则、把规则当建议
4. 首句没在宣布「我要做啥」，尾句没在复述或问「还有别的吗」
5. 每个否定词都在，代码段、路径、数字、错误行逐字精确
6. 没有一句可被双重解读；有就改成完整句
