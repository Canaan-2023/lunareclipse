# 代码库侦察（先理解后修改）

> **领域级技能 · 接入说明**：本技能属于「代码」领域大类（domain: `code`）。安装后落位 `skills_domains/code/`，运行期不注入技能清单——系统只注入领域名与技能数量，AI 自行用 Grep/Glob 检索 `skills_domains/code/` 目录定位 SKILL.md（frontmatter 的 name/description 判断是否匹配），再用 `use_skill(skill_name=codebase-inspection)` 加载本技能正文后执行；正文开头的触发条件就是「何时该加载本技能」的信号。

修改不熟悉的代码库前，先建立结构认知，避免改错地方。

## 流程

1. **读入口与地图**：README、docs/、项目根目录结构——项目自己写的文档最准
2. **看配置**：package.json / pyproject.toml / config 文件——依赖、脚本、入口
3. **找相关代码**：
   - 用搜索（search_files/glob）定位关键词：功能名、API 名、组件名
   - 从调用链追踪：入口 → 处理 → 存储/渲染，画清数据流
4. **确认现状再改**：动手前能说清"这个功能在哪个文件、数据怎么流"，改起来才不会错

## 侦察产出

向用户汇报（简短）：

```
## 结构认知
- 入口：xxx
- 相关文件：xxx（职责一句话）
- 数据流：A → B → C
- 改动点：准备动哪里、为什么
```

## Gotchas

- **别只读一个文件**：改 A 前确认谁调用 A、A 调用了谁（影响面）
- **文档可能过时**：以代码实况为准，文档只做线索
- **同名不同物**：搜索命中多个结果时，用上下文区分（组件 vs 工具函数 vs 类型）
- **改完验证**：结构认知是猜测，改完跑测试/看运行结果确认猜对了

## 完成标准

- [ ] 已定位入口、配置与相关文件，能画出改动点数据流
- [ ] 已确认改动影响面（谁调用它、它调用谁）
- [ ] 已向用户输出结构认知（入口、相关文件、数据流、改动点）
