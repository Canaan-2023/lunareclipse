# 代码简化（Simplify）

> **领域级技能 · 接入说明**：本技能属于「代码」领域大类（domain: `code`）。安装后落位 `skills_domains/code/`，运行期不注入技能清单——系统只注入领域名与技能数量，AI 自行用 Grep/Glob 检索 `skills_domains/code/` 目录定位 SKILL.md（frontmatter 的 name/description 判断是否匹配），再用 `use_skill(skill_name=simplify-code)` 加载本技能正文后执行；正文开头的触发条件就是「何时该加载本技能」的信号。

在不改变行为的前提下，让代码更小、更清晰、更好维护。

## 流程

1. **建立基线**：先跑测试确认当前全绿（没有测试保护的简化是赌博）
2. **找冗余**：
   - 重复代码（同一逻辑多处复制）→ 提函数/组件
   - 死代码（定义了没人用）→ 删
   - 过度防御（不可能为空的 null 检查、无意义的兜底）→ 删
   - 深层嵌套（if/for 套 3 层以上）→ 提前返回/拆函数
3. **逐步简化**：一次一个改动，每步跑测试确认没改坏
4. **收尾**：全量测试 + typecheck，确认行为不变

## 简化优先级

1. 删死代码（零风险）
2. 提取重复（中风险，测试兜底）
3. 简化嵌套/长函数（中风险）
4. 重构数据结构（高风险，先出方案）

## Gotchas

- **别动行为**：简化 = 结构变化 + 行为不变。输出格式、错误信息、边界行为都要保持
- **每步验证**：一次改 10 处再跑测试，出错定位困难；一次一处最稳
- **别过度抽象**：只用一次的抽象是负优化；等重复出现第二次再提
- **注释别删**：简化代码不简化注释——解释"为什么"的注释保留

## 完成标准

- [ ] 简化后行为不变（输出格式、错误信息、边界行为逐项核对）
- [ ] 每步改动后跑测试确认，没有一次改多处
- [ ] 没有引入只使用一次的过度抽象
- [ ] 解释"为什么"的注释保留
