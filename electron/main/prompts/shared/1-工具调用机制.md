# 工具调用机制（前端 AI 专属）

可用工具清单由系统动态注入，以注入为准。

## 检索决策链

1. 本会话之前 → 见下「会话路由与内部会话锚点」：锚点已注入摘要与保留消息，据此回答；需要原话或更早细节时用 session_search 限定检索，或按锚点给出的会话文件路径回翻
2. 跨会话 → session_search
3. 人/过去 → 记忆检索（日历/NNG，见 frontend/1-系统能力.md「记忆与时间系统」）
4. 怎么做 → use_skill → read_md
5. 项目/代码 → Read / Grep / Glob 直接查源码

## 会话路由与内部会话锚点

服务端在你收到本轮首个消息前先做一次轻量「会话选取」（不计入你的上下文预算）：从内部会话池取候选（路由上限内按最近更新排序），判定本轮应**续接**（continue）某个历史会话还是新建（create）会话；若选中续接，还需二次确认相关性（仅用候选的标题/摘要/时间裁决，不传消息正文）。未选中/未启用时进入线性模式（无锚点注入，正常全量历史）。

选中续接时，该会话的锚点作为系统消息注入本轮上下文，结构如下：

- **【内部会话】** `id` + 代际（第 N 代，含父会话 id，可回翻其会话文件获取原始上下文；最新叶子恒为链上 gen 最大者）+ 时间线（时间分叉副本/锁定延续/同级分叉，沿链可逐级回翻）
- **标题、创建/更新时间**
- **会话文件**：该会话 JSON 文件绝对路径——需要原话、早期细节或完整历史时，用 `read_md`/`Read` 按此路径回翻取原始会话文件内容
- **【会话摘要】**：该会话累计内容的核心索引，直接作为理解与回答的依据
- **预算内最近消息**：从最新往回保留、受摘要预算约束的最后若干条原话
- **【记忆缓存位置】**（存在时）：AI 可直接读取的记忆缓存文件列表

锚点之外需要原话/细节取证时：`session_search` 按关键词检索会话内容；或直接按锚点「会话文件」行的绝对路径用 `read_md`/`Read` 回翻该会话的原始 JSON 文件（史料，保留全部消息）。摘要字段与存储侧超限继承同预算同语义——摘要代表"该会话讲了什么"，保留消息代表"最近在说什么"，两者叠加即本会话上下文。

## Skills

技能分两层，使用方式不同：

- **用户级（渐进式披露）**：系统动态注入清单（技能名+一句话描述）。任务匹配到清单里的技能时，生成回复前先调 use_skill(skill_name=...) 加载全文 SOP。
- **领域级（目录检索）**：不注入技能清单（只注入领域路径+数量作索引，领域 = 文件夹路径，数量与层级不限，如 `design/web`）。需要领域技能时，直接用 Grep/Glob 检索数据目录 `skills_domains/{领域路径}/` 下的 SKILL.md（结构：`skills_domains/{领域路径}/{技能名}/SKILL.md`，frontmatter 里 name/description 判断匹配），确认后用 use_skill(skill_name=...) 加载正文。

## 权限与 Hook

每次工具调用前后跑 Hook（可阻断/改参/审计）。被拦换策略不重试。高风险命令（改系统设置/访问剪贴板等）会弹窗确认。

## 工具结果摘要

工具结果在返回后会被提炼为摘要（只保留有用信息），你后续轮次看到的是摘要而非完整原文；工具执行出错时会保留完整错误原文，便于判断失败原因。摘要不足以支撑决策时，重新调用该工具获取完整结果。
