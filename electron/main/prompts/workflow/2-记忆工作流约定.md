# 记忆工作流约定

> 本文件是记忆工作流的公共约定：四层结构与文件命名、描述规则、关系处理口径、铁律。
> 主调度器、NNG 子 AGENT、质量审查共同遵守；日记撰写节点只遵循 2.1 的日记与索引命名部分。

## 一、谁做什么

```
对话写入 RAW → 主调度器（判断记不记 + 命名 + 建记忆）→ NNG 子 AGENT（定位 + 关联维护）→ 质量审查（查结构）
```

- **主调度器**：判断"记不记"，写出记忆文件，不碰 NNG。
- **NNG 子 AGENT**：判断"放哪里"，只做 NNG；张力/桥接时成对补建记忆。
- **质量审查**：只查结构（格式/归属/命名/层级/归档），不重做价值判断。
- **缓存**：由系统按 NNG 自动生成，你不写缓存文件。

## 二、四层结构与文件命名（核心）

本节的路径都是当前用户与 AI 作用域的真实绝对路径，可直接使用；`{YYYY}`、`{序号}`、`{关键词}`、`{name}` 仍是占位含义，按实际值填。

### 2.1 RAW（原始对话流水）

`{RAW 目录}/{YYYY}/{MM}/{DD}/{序号}_{关键词}.md`

- 序号 = 该日内的自增整数，不补零。
- 关键词 = 对话核心主题凝练（决策/偏好/根因/方法论/项目方向），≤20 字，仅汉字/字母/数字/下划线。
- 未重命名的 `{序号}.md` 是正常中间态；重命名后文件名即主题，后续节点少读一遍内容。
- 日记：当天 RAW 目录下 `diary.md`，按日一份；索引在 `{日记索引目录}/{YYYY}/{MM}/index.json`（含标题/摘要/日期 → 文件）。

### 2.2 记忆（提炼产物）

`{normal 目录}` / `{meta 目录}` / `{high 目录}` 下的 `{YYYY}/{MM}/{DD}/{序号}_{域词}_{主题词}_{状态词}.json`

- **序号跟 RAW 走**：RAW#3 产生的记忆一律 `3_...`，由工具从 RAW来源 自动解析，不手填（序号不补零）；同一 RAW 的多条记忆共享同一序号前缀，靠描述区分（如 `3_系统_xxx` / `3_用户_yyy`）。
- **域词** = 所属领域（记忆/图/工作流/工具/模型/界面/用户/缺陷…按内容最自然的域）。
- **主题词** = 内容核心关键词压缩 1-3 个词（中文内容用中文，代码/术语保留英文；复合主题主概念在前）。
- **状态词** = 结论性质（定案/修复/新增/验证/移除/设计/重构/记录…按内容最贴切）。
- 只允许 汉字/字母/数字/下划线；文件名中的 `\ / : * ? " < > |` 会被自动替换成下划线。
- 禁止流水账长句、禁止堆过程细节。
- **自检三问**：只看文件名能否答出——哪域？讲什么？什么性质？答不出即是命名失败。
- 日期目录 = 对话发生日期（时间戳取对话对的时间，不是当前时间）。

### 2.3 NNG（记忆图节点）

`{NNG 根}/{类型前缀}{name}_nng.json` + 同名文件夹 `{类型前缀}{name}/`，一级索引 `root.json` 在 `{NNG 根}`，一级节点在 `{NNG 一级节点目录}/`

- **文件名构成**：类型前缀 + 语义名 + `_nng.json`。类型前缀：普通节点为空，meta 节点 `meta_`，high 节点 `high_`（由 create_nng 自动加，自己再写会双前缀）。同名文件夹 = 去掉 `_nng.json` 的同一串（如 `工程开发_nng.json` ↔ `工程开发/`）。
- 物理结构 = 「JSON 文件 + 同名文件夹」；**层级只由文件夹位置表达，文件名不带层级序号**：
  一级在 `{NNG 一级节点目录}/`，二级在 `{NNG 一级节点目录}/{一级节点同名文件夹}/`，以此类推，层级无上限。
- **name = 语义短语**（用户偏好/工程开发/登录认证），让人和 AI 一眼看懂；禁止 1、a、杂项、临时这类名字。name 本身不含 `_nng`、层级号、type 前缀，这些由工具补齐。
- **描述 ≤200 字（硬上限）**：描述是导航标签不是正文；接近上限说明节点装太杂 → 建子节点分层收纳，不往描述里堆。
- 归档区跟随节点位置：一级节点归档到 `{NNG 一级节点目录}/archive/`，二级节点归档到 `{NNG 一级节点目录}/{父节点}/archive/`。

### 2.4 缓存（检索镜像）

`{缓存一级索引}`（一级缓存索引）+ `{一级缓存目录}/{类型前缀}{name}_cache.json` + 同名文件夹 `{类型前缀}{name}/`，结构与 NNG 相同（`index.json` ↔ `root.json`），由系统按 NNG 自动生成。

- 缓存文件名 = 与它对应的 NNG 同名段 + `_cache.json`（普通无前缀，meta_ / high_ 与 NNG 一致），同名文件夹结构一一对应。
- 引用字段是 `记忆路径`（已是精简快照，读缓存可免读记忆全文）。
- 只读：手写缓存与 NNG 不一致，下次同步会被覆盖或留下脏数据。

### 2.5 归档

- 归档 = `MoveFile` 到节点所在文件夹的 `archive/` 子目录，**不是删除**（保留历史可追溯）。
- **记忆文件永不移动、永不归档**：记忆的"归档"语义 = 写入 NNG 关联，节点就是归档层。
- 只有 NNG 文件允许 MoveFile。

## 三、描述是导航依据（三问）

每个 NNG 的描述必须回答：

1. 这个节点装什么、覆盖什么范围？
2. 只看描述，能不能判断一条新记忆该不该进这个节点？
3. 是不是已经逼近 200 字？是 → 说明该拆子节点了。

描述留空 = 这个节点等于不存在；描述写推导原因 = 放错了东西（推导原因属于 meta 记忆的精炼内容，描述只写"放什么"）。

## 四、关系处理口径（唯一术语表）

| 术语 | 判定 | 处理 |
|---|---|---|
| 重复 | 语义相同、表述不同 | 归并到目标 NNG；源记忆原地保留；归并后源 NNG 关联记忆变空 → 该空 NNG 归档 |
| 矛盾 | 同主题冲突结论，"旧版本不再有效" | 旧 NNG 归档 → 原位置同 name 重建（只装新记忆）→ 归档 NNG 只装旧记忆并补 `归档记录` |
| 张力 | 同主题冲突结论 / 不同价值取向 | 建 `high`：记忆 + 节点成对，节点挂在受影响节点之下，禁止建在一级 |
| 桥接 | 跨领域、无法直接推导但确有关系 | 建 `meta`：记忆 + 节点成对，描述只写放什么，`下级NNG` 手动填目标节点路径 |
| 聚合收纳 | 单条孤立、无父级可归、无法桥接 | 建聚合型 `meta`（元认知第二形态）：用最大集合概念做 name，描述注明"后续同类可继续归入" |

## 五、铁律（违反 = 审查必判疏漏）

1. **记忆永不归档**：MoveFile 的目标路径禁止落在记忆工作域（{记忆工作域}）内。
2. **每个记忆必须有对应 NNG**：不允许任何记忆无节点归属。
3. **只有 NNG 可 MoveFile**，且归档到原位置的 `archive/`。
4. **类型对应**：normal 记忆→普通 NNG；meta 记忆→meta NNG；high 记忆→high NNG，不能混。
5. **成对原则**：建 high/meta 时，记忆与 NNG 必须成对创建。
6. **high 禁止一级**：high 是张力的产物，必须挂在受影响节点之下；没上级的 high 应为普通 NNG。
7. **描述必填且 ≤200 字**：本轮涉及的所有 NNG（新建/合并保留/归并目标）都要有覆盖全部关联记忆的描述。
